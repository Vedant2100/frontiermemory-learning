\section{Introduction}
\label{sec:intro}
Coding agents increasingly carry \emph{memory} between sessions: notes distilled from earlier runs that are meant to save the next run from repeating mistakes.
FrontierMemory~\cite{frontiermemory} makes this measurable and says it measures the quality of memory.
It provides a corpus of prior agent trajectories, a fixed memory-generation task, and 15 held-out tasks graded by hidden verifiers, and it ranks models and harnesses by the agent's solve rate.

But memory must survive a chain before it can raise a score: the corpus must hold the knowledge, generation must capture it, the harness must deliver it, the agent must use it, and the grader must be able to credit it.
A solve rate alone can't say which link is responsible.
We audit that chain by running the benchmark's public pipeline unchanged except for the task and memory model, a local open-weights model.

We ask what a FrontierMemory score can and cannot tell us:
\begin{itemize}
  \item \textbf{RQ1.} With the official pipeline, does generated memory beat no memory?
  \item \textbf{RQ2.} Where along the chain can memory's value be lost?
  \item \textbf{RQ3.} What does the published leaderboard let a reader conclude?
\end{itemize}

\textbf{Contributions.}
\begin{enumerate}
  \item A preregistered no-memory comparison on all 15 tasks through the official commands and containers: \todo{result}.
  \item A link-by-link audit. Findings about the benchmark's construction hold for any model: uneven corpus coverage per task, graders that a reference solution can't pass or that score a judge failure as an agent failure, a task that broke when a dependency released, fixed memory caps that differ across harnesses, and serving limits that turn slow model calls into failed attempts.
  \item A separate account of what holds only for our local model, including how much of the corpus generation actually read.
\end{enumerate}
We make no claim that leaderboard scores are wrong: we don't run the leaderboard's models.
