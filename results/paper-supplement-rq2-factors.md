# RQ2 factors table, full text (supplement to Table II)

The paper's Table II (what can keep memory from improving a score) is cut to fit four pages. This is the complete text of every row before the cut; nothing here is new evidence. S: source or documentation. O: observed with the official pipeline. L: specific to our local model.

| Link | Finding | Basis |
|---|---|---|
| Corpus | At 50% distinctive-token overlap, no run matches 8 of 15 tasks in either corpus version (5 at 30% on v1.1). DAPT has 35 matches, none passing; same-repository runs with different prompts may still help. | O |
| Generation | Memory is exported only when generation ends, so a timeout leaves none. | S, O |
| Generation | Three generations took 21 to 27 minutes of the 6 hours allowed. Run 2's generation delegated work to sub-agents that queued on the single model slot (median wait 10 minutes) and hit the limit with no memory. On a second GPU type that decodes about 1.5x slower, with identical serving settings, a generation timed out the same way, so the 6-hour limit may tie memory to serving capacity. One generation printed about 0.2% of the corpus to itself (290KB of 126MB). | L |
| Harness | Index caps are fixed regardless of the context window: 2,500 tokens in Codex and 200 lines or 25KB in Claude Code, so 21% and 48% of the same entry file is visible at start. Hermes shows the whole entry file and a skill index, but that was 1 of 13 files of our run-1 memory; the rest must be opened. | S, O |
| Harness | At the highest effort, Hermes cancels a model call after 300s, but the cancel does not stop the server, so retries queue behind abandoned calls; after 5 it gives up, and the trial scores 0 and counts as valid. Hermes's post-answer memory review is cut when the trial's container stops. Text configured as an extra system prompt reaches every call but is never saved to the session log, so checks of what the model saw that read saved logs under-report it. | S, O |
| Agent | In run 1 the agent opened a memory file in 15 of 45 trials, never on 7 of 15 tasks. Of its 7 passes, 2 followed an open (both Word2Vec); 5 passed without opening memory beyond what was shown. In an exploratory arm, one added sentence telling the agent to read its memory raised opens to 27 of 45 trials and moved no score (8 vs 7 passes of 45); showing every file at the start, or none, gave 7 and 9 passes of 45. | L |
| Recency | A mechanical check found no changing package pins across matched runs. It could not check conflicts in prose, and 5 tasks lacked matched runs. We found no direct test of resolving stale information. | O |
| Grader | The reference solution scores 0 on 4 of 15 tasks, as the maintainers document: on cattrs and cookie store it passes the functional tests but not the hidden preference checks, and on both EnterpriseOps tasks its trace is empty. Without memory, our agent met every hidden preference on cookie store in 1 of 3 counted attempts and passed EnterpriseOps CSM in 2 of 3; on cattrs it did so once in the discarded first control. These preferences can therefore be met without memory; with run-1 memory, no cookie-store attempt met all of them. EnterpriseOps Teams passed exactly 3 of 4 checks in all 6 attempts of the control and run 1. | O |
| Grader | In the grading code, a failed LLM judge yields reward 0 and a valid trial, indistinguishable from an agent failing. The task files and the CLI name different judges, and the leaderboard does not say which was used. | S |
| Serving | Harbor's egress proxy, which enforces no-network tasks, drops a model response not started within 15s. Any slower model hits it; the agent gives up and the trial counts as a valid failure (3 of 41 trials in a discarded first control). A malformed tool call from the model surfaces as an HTTP 500 (1 in about 4,100 calls, recovered by retry). | O |
| Build | Harbor rebuilds images per trial, and 12 of 15 tasks have install commands in their builds. One task broke without any change on the benchmark's side when a dependency released on Nov 1; another built to a different image from identical files. | S, O |
